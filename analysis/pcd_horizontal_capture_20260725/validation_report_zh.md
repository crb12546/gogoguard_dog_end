# PCD 重力水平录制改造与验证报告

日期：2026-07-25

## 根因

旧管理台点云录制器直接订阅 FAST-LIO 的 `/cloud_registered`，随后把其中的
`x/y/z` 原样保存为 PCD。这个话题位于本次 FAST-LIO 会话的 map 坐标系；外接
MID-360 固定斜装时，该 map 坐标系不保证与重力水平面一致。旧保存链路没有任何
map-to-ground 旋转，因此导出的 PCD 会整体倾斜。

仓库里的旧 `level_pcd.py` 默认写死约 `13°`，它既不是本次会话的实测角度，也
无法适应 FAST-LIO 每次启动后不同的 map 朝向，不能作为正式修复。

## 实现

新版录制器在采点前同时接收：

1. FAST-LIO `/Odometry` 的完整位置与四元数；
2. 外接雷达 `/livox/imu` 的重力与角速度；
3. 狗本体 `/lf/sportmodestate` 的 IMU 重力与角速度。

狗保持静止时，两套独立重力来源必须在标定外参下相互同意，并连续通过 15 个
样本。随后录制器冻结唯一的 `q_ground_from_map`，停止采集时对所有点执行：

`p_ground = q_ground_from_map * p_fastlio_map`

这里只执行一个正交、行列式为 1 的三维刚体旋转：

- 不缩放；
- 不拉伸；
- 不把 Z 清零；
- 不按百分位平移高度；
- 不凭固定角度猜测；
- 不使用指南针强行设置 yaw。

## 输出

- `maps/console/名称.pcd`：重力水平版，管理台默认显示和下载这个文件；
- `maps/console/raw/名称.pcd`：原始 FAST-LIO 倾斜 map 点云；
- `maps/console/名称.leveling.json`：校准来源、两套 IMU 一致性、冻结四元数、
  旋转矩阵、点数、边界、文件哈希和刚体不变性证明。

如果重力水平面未锁定，录制器明确返回 `LEVEL_FRAME_NOT_READY`，不会生成一个
看似可用但角度未经证明的主 PCD。

## 自动测试

管理台完整测试集共 57 项，全部通过。新增几何测试证明：

- 已知倾斜平面旋转后的法向与 `(0,0,1)` 一致；
- 旋转前后任意两点距离保持不变；
- PCD 头部、点数和数据行数一致；
- 固定安装标定文件包含来源哈希且四元数有效；
- 远端启动命令同时注入录制器、水平变换和标定证据，并通过 shell 语法检查。

## 真实旧 PCD 文件级验证

验证对象：
`dog_xunjian_backup/20260723_codex_01/go2_fastlio_ws/maps/console/xbf2.pcd`

- 输入点数：`816024`
- 所有坐标均为有限数；
- 原始边界：
  - X：`-43.1497 ~ 335.6533 m`
  - Y：`-224.5924 ~ 59.2061 m`
  - Z：`-5.9947 ~ 209.4958 m`
- 从真实点云抽样得到的主平面法向约为
  `(-0.418895, 0.176046, 0.890806)`，相对重力水平倾斜约 `27.0253°`。

用新版同一刚体旋转函数做文件级测试后：

- 输出 PCD 头部点数：`816024`
- 输出数据行数：`816024`
- 总行数：`816035`，等于 11 行头部加全部点；
- 512 个实点抽样的最大两点距离变化：
  `1.1368683772161603e-13 m`；
- 主平面旋转后法向：
  `(5.55e-17, -2.78e-17, 1.0)`；

这项旧文件验证只用于证明 PCD 读写及刚体变换不会损坏点云。正式新录制不会用
几何拟合去猜地面，而是使用录制当时三种实时传感器共同证明的重力方向。

## 现场使用

1. 启动雷达与 FAST-LIO，等底座正常。
2. 输入点云名并点“开始采集”。
3. 保持狗静止，直到页面显示“水平校准完成，采集中”。
4. 再遥控带狗走完建图区域。
5. 点“结束保存”，等水平版、原始版和证据 JSON 全部保存完成。

管理台 `http://127.0.0.1:8642` 已重启并加载新版。由于开发期间机器狗已经离开
电脑连接范围，第一份新 PCD 的现场传感器输出仍需在机器狗回来后做最终核对。
