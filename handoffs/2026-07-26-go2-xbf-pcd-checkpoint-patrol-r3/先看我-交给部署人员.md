# Go2 XBF 自动校准交付说明（R3）

这是当前最新交付版。`R3` 是交付包版本；内部地图和路线仍叫 `R2`，因为没有
伪造一次新的现场审核版本。

## 直接结论

本包固定绑定以下一套数据，不需要部署人员再次选择标记物：

- PCD：`xbf-2 2.pcd`；
- CSV：`xbf9_horizontal_clean.csv`；
- 部署路线：1277 点、约 602.4 m；
- 中途停车校准点：waypoint 373、585、787；
- 稳定组合：路灯 H + K01 路沿、路灯 I + K-B 路沿、C01 建筑直角 + K-A
  路沿。

定位成功会自动开始巡检；三个 checkpoint 定位成功会自动继续。没有网页审批
或每次人工“同意”按钮。

## 机器狗实际执行流程

1. 狗放在路线起点约 2 m 内，粗略方向误差约 35°内。
2. 启动后运动输出保持为零，采集 5 组 MID-360 扫描。
3. 实时点云与起点附近 PCD 静态几何做多初值 NDT/GICP。
4. 5 次独立结果在至少 2 秒内一致后，冻结 `map<-odom`。
5. 原 `waypoint_follower_go2_2` 使用校准后的 odometry 跟随 CSV。
6. 到 373、585、787 时先停车，再做同样的多帧配准。
7. 新的 `map<-odom` 通过后，原 follower 从当前路线进度自动继续。

普通行走期间关闭 NDT/GICP，所以不会每 5 秒或 10 秒抢占算力。

## 第一次到现场

代码不设置人工放行门，但当前只有 PCD 和 CSV，没有同步建图轨迹或现场控制点。
离线分析能稳定确定约 `-15.6°～-15.8°` 的整体旋转，却不能从这两个文件唯一
消除约 1 m 以上的横向平移平台。因此第一次只能把它当作一次新任务现场验收，
不能把“能编译”误写成“已经实测完成 600 m”。

先只定位：

```bash
export GO2_XBF_CALIBRATION_ONLY=1
bash scripts/start_xbf_patrol.sh
```

停止后，正式短测前必须清掉该变量：

```bash
unset GO2_XBF_CALIBRATION_ONLY
export GO2_XBF_PATROL_SPEED=0.10
export GO2_XBF_MAX_YAW_RATE=0.30
bash scripts/start_xbf_patrol.sh
```

先走 5～10 m，肉眼只确认路线落在真实可走路面上；随后验证 waypoint 373 能
停车、定位并自动继续。通过后再恢复默认 `0.20 m/s` 跑完整路线。这是当前
PCD/CSV 一次性的现场闭合，不是以后每次巡检都要审批。

如果短测发现整条路线横向平移，停止任务并记录
`/tmp/go2_xbf_patrol/logs/`；这是 CSV→PCD 离线叠放问题，单靠 checkpoint
不能把一条整体放错的路线变成正确路线。
